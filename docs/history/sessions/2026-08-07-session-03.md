## What happened

Separately from this project's Claude sessions, the owner worked directly
with Gemini for roughly 4 hours to build and deploy a working version of
the app. Gemini pushed **6 commits directly to `main`** (`44827b6` through
`ecd9c7c`), with no pull request and no review — bypassing
[`../../engineering/git-workflow.md`](../../engineering/git-workflow.md)'s
"never push straight to `main`" rule entirely. Nothing from this project's
own work was lost — [PR #2](https://github.com/singhashish8-spec/Architect-AR/pull/2)
(Phase 1: schema, upload/view flow, BIM tap-to-inspect, IFC parsing, local
preview, 12 tests) is untouched on its branch — but `main` now runs a
different, much simpler app than what PR #2 builds toward. The two have
diverged and need reconciling.

## What Gemini's version actually is

A single-page app (`web/src/App.tsx`, no routing, no Supabase): a text
input where the user pastes a public `.glb` URL directly, which renders
via `<model-viewer>` with AR enabled. Model files are hosted on
**Cloudflare R2** (the owner set this up during the session), referenced
by pasting the R2 public URL by hand each time — no persistence, no saved
projects, no shareable clean link (`/p/:id`-style).

## Assessment: real regressions, one real gain

**Regressions, not stylistic differences:**
- `// @ts-nocheck` at the top of `App.tsx` disables type-checking for the
  entire file. The bug it was used to dodge — `<model-viewer>` not
  recognized as a valid JSX element — is the **exact same bug already
  fixed correctly** on the PR #2 branch, in
  `web/src/types/model-viewer.d.ts`: the fix is
  `declare module 'react' { namespace JSX {...} } }`, not
  `declare global { namespace JSX {...} } }` (the pattern Gemini's session
  tried, per its own write-up, before giving up and reaching for
  `@ts-nocheck`). React 19's `react-jsx` transform resolves
  `IntrinsicElements` through the `react` module specifically — this is
  documented in this project's own code, not a new discovery Gemini's
  session needed to make blind.
- No BIM tap-to-inspect, no scale presets, no persisted/shareable
  projects — the product's core differentiator (tap a wall, see its Revit
  data) and the "unlisted link" sharing model are both gone. What remains
  is closer to a raw `<model-viewer>` demo than the Phase 1 spec in
  [`../../roadmap/phases.md`](../../roadmap/phases.md).
- No automated tests (PR #2 has 12, covering the scale math, IFC value
  unwrapping, and the scale-preset dropdown contents).

**One real gain, worth keeping:** it's an actual live, working Vercel
deployment — further than this project's own Claude sessions got, since
Supabase/Vercel sign-up was still pending on the owner's side. **Cloudflare
R2 as the storage backend is also a legitimately good call** — S3-compatible,
proper CORS support for cross-origin `fetch()`, no egress fees, and
critically, none of Google Drive's virus-scan-interstitial problem that
was flagged as a real risk to the "paste a Drive link" idea discussed
earlier this session (see
[`../../roadmap/decisions.md`](../../roadmap/decisions.md)). Worth adopting
as the Storage layer in place of Supabase Storage — properly, via an
upload flow, not manual URL paste-in.
