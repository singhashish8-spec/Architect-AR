| Could the app read a Revit file (or a consolidated Navisworks NWC) directly, getting geometry + real textures + full properties from one file instead of two? | **Researched 2026-08-15, decided not to pursue for now** — the owner's firm already produces one consolidated NWC per project (all disciplines linked, already used for clash detection), which would solve the earlier multi-discipline-file problem for free. But NWC is a closed Autodesk format with no open-source parser (unlike IFC's `web-ifc`), so reading it at all requires Autodesk's own cloud service, Autodesk Platform Services (APS, formerly "Forge") — researched in detail and found to carry more real risk than benefit right now: Model Derivative (their translation API) has **no glTF/GLB output for any source format**, only their own proprietary SVF/SVF2 (consumable only via Autodesk's own Viewer SDK, not this app's three.js pipeline); the one community project that bridged SVF→GLB was archived/unmaintained as of March 2026; NWC's real-texture fidelity through translation is unconfirmed; and Autodesk's entire developer billing model was overhauled in December 2025 with no publicly confirmed per-translation dollar price found. Given the app's actual two stated goals (client review, quantity takeoffs) already work today via the free, fully client-side IFC+FBX pipeline, adopting APS would trade a working free pipeline for an unconfirmed-cost, unconfirmed-fidelity cloud dependency requiring either a second viewer (Autodesk's own) or a fragile from-scratch SVF→GLB conversion step. Revisit only with a concrete Autodesk quote and a real test translation of one of the owner's own NWC files in hand — see [`history/sessions/2026-08-15-session-10.md`](../history/sessions/2026-08-15-session-10.md). |
